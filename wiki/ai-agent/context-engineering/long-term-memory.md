> 本文根据 DeepWiki 的 [长期记忆与存储问答](../../raw/2026-09-22-153921.md)及 [记忆源码与模板](../../raw/2026-09-22-153917.md#q6)整理。

**任务状态帮助同一个任务继续，长期记忆帮助后来的任务少走弯路。** 保存聊天记录只是留下经历；要形成记忆，还需要选出值得复用的信息，整理成可查阅的内容，并在相关任务中使用。

## 怎样形成：先提取一次经历，再整理多次经验

**Codex 的记忆写入分为提取和整合两个阶段。** 提取关注一次会话里有什么值得留下，整合负责把新经验放进已有知识中，减少重复并处理冲突。

```text
符合条件的历史会话
    → 提取候选经验与会话摘要
    → 保存候选及来源
    → 与已有经验整合
    → 更新记忆摘要和详细手册
```

提取在满足条件的后台流程中进行，选择近期、已空闲的会话处理；不是每完成一步就立即写入长期记忆。候选先进入 SQLite，再由整合阶段更新记忆文件。**生成了候选，不等于后续模型已经读到了这条经验。** [两阶段流程](../../raw/2026-09-22-153917.md#q6)。

## 留下什么：能复用，还要有依据

**值得保留的是稳定偏好、项目约定和已验证经验，而不是所有对话细节。** 例如某项目的测试方法、工具失败的条件和验证有效的解决办法，都可能帮助下次工作。

| 需要保留的要素 | 作用 |
| --- | --- |
| 经验内容 | 下次遇到类似问题可以怎么做 |
| 适用范围 | 避免把一个项目的约定套到其他项目 |
| 来源与时间 | 方便回查，并判断是否可能过期 |
| 验证情况 | 区分已证实结论与尚待验证的猜测 |

Codex 的整合模板强调用户明确陈述、实际采纳和工具验证的证据。**模型提出过一个建议，不等于用户接受了它；一次尝试成功，也不等于任何环境都适用。** 这些要求主要靠提取与整合提示词落实，不能当作程序已逐条验证所有记忆的保证。[提取原则](../../raw/2026-09-22-153921.md#q2)。

## 保存与读取：摘要做入口，手册放细节

**记忆越积越多，不能每次都把全部内容塞进上下文。** 所附模板将轻量的导航摘要与详细经验分开：先让模型知道有哪些相关资料，再按需要查阅。

| 保存位置或文件 | 主要职责 |
| --- | --- |
| SQLite | 保存候选经验、来源、处理状态和使用统计 |
| `raw_memories.md` | 汇集供整合阶段处理的候选材料 |
| `rollout_summaries/` | 保存会话摘要，提供来源线索 |
| `MEMORY.md` | 整理可搜索、可查阅的详细经验 |
| `memory_summary.md` | 提供简短导航，帮助定位相关经验 |

**数据库方便管理处理过程，文件方便阅读和查找经验。** 模板要求导航摘要常驻、详细手册按需查阅；材料未完整展示读取侧调用链，因此这里说明的是该设计，而不是保证每次请求都按同一路径加载。[文件分工与模板](../../raw/2026-09-22-153917.md#q6)。

## 怎样更新：确认范围，再处理冲突和遗忘

**新信息不一定推翻旧信息，先要确认它们是否适用于同一范围。** 一个项目要求中文报告，另一个要求英文，可以同时成立；同一项目明确更改要求时，才需要更新对应经验和导航摘要。[更新原则](../../raw/2026-09-22-153921.md#q3)。

更新还应保留证据强弱：用户明确的新要求可以替换旧要求，未经验证的新猜测不应轻易覆盖已有结论。不能只比较时间戳，就认定最新内容一定正确。

**遗忘也要覆盖整理后的内容。** 删除一条候选后，如果手册和摘要仍保留它的结论，未来任务仍可能继续使用。整合模板要求清理失去依据的内容，并保留仍有其他来源支持的部分；数据库、记忆文件和已加载上下文之间的完整删除一致性，材料尚未给出保证。[遗忘机制](../../raw/2026-09-22-153921.md#q3)。

长期记忆的价值在于让后续任务获得相关、可信、仍然有效的经验；存得更多，本身并不代表记得更好。
