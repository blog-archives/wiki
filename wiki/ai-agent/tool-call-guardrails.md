> 本文整理自 DeepWiki 的 [工具大结果处理](../raw/2026-09-22-091325.md)与 [重复工具调用检测](../raw/2026-09-22-110356.md)问答，提炼控制上下文体积与避免无进展调用的核心思路。

## 结果太大：限制进入上下文的内容

**完整结果与模型当前需要读取的内容，可以分开保存。** 常见做法是就地截断，或把完整结果落盘，只返回预览和文件路径；前者简单，后者便于模型继续搜索、分段读取。

| 做法 | 核心处理 | 适用取舍 |
| --- | --- | --- |
| 截断 | 按字节或 Token 预算保留片段，明确标记省略 | 只需要概览；未另存副本的部分无法从该结果取回 |
| 落盘 + 引用 | 保存完整结果，返回预览、路径与读取方式 | 日志、网页等后续可能需要精查的内容 |
| 限定读取范围 | 让工具支持分页、行范围、过滤或搜索 | 从源头减少无关内容，避免每次取回全部结果 |

**已有实现可以作为选型参考。** 所附 Codex 材料展示多处按预算截断；Crush 按工具分别采用网页落盘、抓取限额或拒绝过大的读取范围；Claude Code 的变更日志记录了大输出落盘并返回文件引用的策略。它们说明处理方式可以随工具语义变化，不必为所有结果强用同一种方案。[原始材料](../raw/2026-09-22-091325.md)。

**应用可统一规定输出预算和返回格式，再由工具选择具体处理方式。** 例如返回“摘要或预览 + 是否省略 + 完整结果位置”，让模型知道当前看到的不是全部内容。UI 折叠只改变展示，只有实际裁剪模型输入，才会减少上下文占用。

## 调用重复：判断是否取得新进展

**按 `call_id` 去重，只能防止同一次调用被重复处理。** 模型可以使用不同 ID，反复请求同一工具、传入相同参数；识别这种无进展行为，需要观察调用内容及结果变化。

**所附实现没有证明存在通用的执行前内容查重。** Claude Code 插件的认领机制防止同一个工具事件重复触发 Hook；Codex 按 ID 记录已执行调用，并限制记录体积，另有历史一致性校验。这些机制各有用途，但都不能等同于“发现相同参数就拒绝执行”。[原始材料](../raw/2026-09-22-110356.md)。

> **Status: Disputed** — 旧文曾概括为“两家只有工具调用次数上限兜底”；材料能确认的 Codex 上限限制的是元数据记录，不阻止执行，也不足以确认产品完整的循环防护策略。

**应用层可以用调用指纹与进展判断补上防线：**

1. **识别相同请求**：对工具名与规范化参数计算指纹，保留会影响语义的字段。
2. **观察结果变化**：在最近调用窗口内计数，结合结果摘要判断是否持续无进展。
3. **先反馈，再停止**：提醒模型改变参数或策略；仍无进展时，按尝试、耗时或 Token 预算结束本轮。

**重复不一定无效，轮询也不应无限继续。** 状态查询即使参数相同，结果仍可能变化；应按工具设置轮询间隔、等待期限和豁免条件。写操作还需要业务幂等键或状态核实，调用指纹不能替代副作用去重。这些是应用设计建议，不是上述产品已实现的统一机制。

相关：[模型调用错误处理](model-call-retry-and-fallback.md)负责请求失败后的恢复；本文关注工具输出体积与调用是否推进任务，对应面试题第 34、43 题。

**结果减量后，还需要保持调用关系与有效要求。** 结果的 `call_id` 配对、缺失输出处理和早期约束的跨摘要保留，见 [上下文完整性](context-engineering/context-integrity.md)；这些机制与执行前查重、业务幂等分别解决不同问题。
