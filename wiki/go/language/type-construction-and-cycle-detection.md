> 本文整理自 [Type Construction and Cycle Detection](https://go.dev/blog/type-construction-and-cycle-detection)。

> **Go 1.26 改进了类型检查器如何构造类型、发现非法循环定义——日常几乎无感；核心是：类型可以先互相引用再补全，但不能靠「尚未定型的自己」算出自己的定义。**

## 类型构造

编译器遍历 AST 时，会为每个类型建内部结构，并填上它指向的依赖类型。例如：

```go
type T []U
type U *int
```

构造顺序大致是：先建 `T`（底层还未知）→ 发现依赖 `[]U` → 再建 `U` → 发现 `*int` → `int` 是预声明类型，已就绪。然后自底向上收尾：`*int` 完成 → `U` 完成 → `[]U` 完成 → `T` 完成。

一个类型 **完整**，意思是：它的内部字段都填好了，且指向的类型也都完整。只有完整类型，才能安全地「拆开看内部」（比如查 map key 是否 comparable、算数组长度）。

## 递归类型

若把上面的 `*int` 换成 `*T`：

```go
type T []U
type U *T
```

走到 `*T` 时，`T` 还在构造中（底层还是空的）。这时不需要知道 `T` 长什么样——指针只是「指向某个类型」的引用。于是先把 `*T` 挂到未完整的 `T` 上，继续往上收；等 `T` 自己填完，环上的类型一起变完整。

关键：这里只是 **引用** `T`，没有去读它的底层结构，所以不完整也没关系。

## Cycle

反过来，有些构造 **必须拆开** 类型才能继续。经典例子：

```go
type T [unsafe.Sizeof(T{})]int     // 非法：算 T 的大小需要先知道 T 的大小
type T [unsafe.Sizeof(new(T))]int  // 合法：指针大小固定，不必看 T 内部
```

`T{}` 的类型是定义类型 `T`，此时 `T` 未完整——名字本身不带底层信息，没法算大小。而 `new(T)` 得到 `*T`，所有指针一样大，不必拆 `T`。

Go 1.26 在 **产生** 这类可能不完整值的地方（转换、调用、断言、解引用等）立刻检查完整性；不完整就报 cycle，返回 `invalid`，不让错误值继续往下传。
