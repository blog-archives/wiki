## 数组

### 核心本质：数组是「值」，不是指针

在 C 语言中，数组名在绝大多数表达式里会隐式退化为指向首元素的指针；使用时往往像在操作「首元素地址」，而不是整块数组值。
而在 Go 里完全不同：

> 数组变量代表的是 **整个数组本身**，它不是一个指向首元素的指针。

数组的类型自带长度信息（比如 `[4]int` 和 `[5]int` 是两个完全不同、彼此不兼容的类型），变量本身承载全部元素的内存数据。

### 直接后果：赋值 / 传参会发生全量拷贝

正因为数组是完整的值，赋值给另一个变量，或作为 `[n]T` 类型的参数传入函数，都会 **拷贝整个数组**。

```go
func modify(arr [3]int) {
    arr[0] = 100 // 修改的是数组副本
}

func main() {
    a := [3]int{1, 2, 3}
    b := a       // 完整拷贝一份数组给 b
    b[0] = 10    // 修改 b 完全不影响 a

    modify(a)    // 函数传参也是传完整副本
    // 执行后 a[0] 依然是 1，不会被修改
}
```

若传的是 `*[3]int`，拷贝的是指针本身，不会复制整个数组；但那就不是数组值的语义了。

### 把数组看作「下标型结构体」

你可以把数组理解成一种特殊的结构体：字段用下标而非名字访问，是一个固定大小的复合值。相当于 `[4]int` 在语义上等价于：

```go
type Array4Int struct {
    e0 int
    e1 int
    e2 int
    e3 int
}
```

因此数组同样是固定大小的复合值——按值赋值、按值传参，语义与结构体一致。

## 切片

数组长度固定、传参会整段拷贝，日常 Go 代码里很少直接用它。切片是在数组之上的一层抽象：类型为 `[]T`，**长度不是类型的一部分**；它本身不持有元素，而是对底层数组某段的描述。

### 内部结构

切片由 **指针、长度、容量** 三部分组成。`make([]byte, 5)` 得到的 `s` 大致如下：

![](https://go.dev/blog/slices-intro/slice-struct.png)

- **len**：当前可见元素个数
- **cap**：从切片指针起，底层数组还能覆盖的元素个数

对 `s` 做 `s = s[2:4]` 时，变的是切片头，底层数组不变：

![](https://go.dev/blog/slices-intro/slice-1.png)

**再切片不会拷贝元素**，只新建一个切片头指向同一段存储。修改子切片的元素会影响原切片：

```go
d := []byte{'r', 'o', 'a', 'd'}
e := d[2:]
e[1] = 'm'
// d == []byte{'r', 'o', 'a', 'm'}
```

若之前把 `s` 切短了，可以用 `s = s[:cap(s)]` 在容量范围内「拉长」可见长度，仍不分配新数组。

### 扩容：copy 与 append

容量不够时，必须分配更大的底层数组，把旧数据拷过去。标准库提供了 `copy(dst, src []T) int`；更常见的是内置 `append`，在需要时自动扩容并返回新切片：

```go
a := make([]int, 1) // []int{0}
a = append(a, 1, 2, 3)
// a == []int{0, 1, 2, 3}

a = append(a, b...) // 把另一个切片 b 的元素追加到 a
```

`nil` 切片与空切片一样，可以直接 `append`，适合在循环里逐步构建结果。

### 一个常见陷阱

再切片共享底层数组，意味着 **只要还有切片引用那段数组，整段数组都不会被 GC**。若从大缓冲里只截取一小段并长期持有，可能白白占住全部内存；需要独立副本时，应 `make` 新切片并用 `copy`（或 `append`）拷出关心的部分。
