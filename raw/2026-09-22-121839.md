# DeepWiki Q&A with Code Context for Repository: anthropics/claude-code
## Q1
模型调用失败后的处理方式什么
### Answer
## 摘要

根据现有索引到的代码上下文,Claude Code 中模型调用失败的处理主要体现在 CHANGELOG 中记录的行为变化,包括**重试机制**、**fallback 模型切换**以及**错误提示优化**,但没有找到具体实现这些逻辑的源码文件(如重试循环、fallback 切换的核心代码)。

---

## 已知的处理方式(来自 CHANGELOG 记录)

### 1. Fallback 模型切换
当主模型过载或不可用时,系统会自动重试一次 fallback 模型: claude-code:2903-2907 

当主模型未找到(not found)时,会切换到 `--fallback-model` 配置的模型,并在剩余会话中持续使用它,而不是每次请求都失败: claude-code:3184-3184 

### 2. 恢复中断的对话轮次
`CLAUDE_CODE_RESUME_INTERRUPTED_TURN` 环境变量控制着 API 错误导致失败后的轮次恢复行为,并有时间窗口限制(`_MAX_AGE_MS`): claude-code:522-522 

### 3. `/goal` 命令的错误恢复
`/goal` 在遇到 API 错误、网络中断或 token 限制时会带退避重试(retry with backoff),或暂停并说明原因,包括等待 usage limit 重置: claude-code:519-519 

`/goal` 遇到不可恢复错误(如凭证失效、额度耗尽、context overflow)时会清空自身状态并给出提示,而不是保持"armed"状态: claude-code:1611-1611 

### 4. 畸形工具调用重试
当模型返回格式错误的工具调用(malformed tool call)时,系统会丢弃这段错误输出,再重试(包括 Bedrock、Vertex、Foundry 场景): claude-code:1152-1152 

### 5. 认证/凭证失效的处理
过期的 AWS/Google Cloud 凭证在某些 host app 下,之前会重试 10 次并给出通用"request failed"提示,现已修复为直接展示重新认证的错误信息: claude-code:691-691 

### 6. 空/畸形响应的错误提示改进
"API returned an empty or malformed response" 错误现在会说明返回的具体内容(content type、body kind、size、request ID)以及原始流式请求失败的原因: claude-code:1606-1606
