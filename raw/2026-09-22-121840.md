## Q1

### Answer
# 模型调用失败的处理方式

在 `cloudwego/eino` 的 `adk` 包中，`ChatModelAgentConfig` 提供两种互补的机制来处理 ChatModel 调用失败：**重试（Retry）** 和 **故障转移（Failover）**，两者可以同时配置，并按"重试耗尽 → 故障转移"的顺序生效 <cite repo="cloudwego/eino" path="adk/chatmodel.go" start="403-414" />。

---

## 1. 重试机制（ModelRetryConfig）

通过 `TypedModelRetryConfig` 配置最大重试次数、退避策略及自定义重试决策逻辑 <cite repo="cloudwego/eino" path="adk/retry_chatmodel.go" start="220-253" />。

- **`ShouldRetry`**：接收 `TypedRetryContext`（包含尝试次数、输入消息、输出消息、错误等），返回 `TypedRetryDecision`，可以决定是否重试、改写错误（`RewriteError`）、修改输入消息（`ModifiedInputMessages`）、追加模型选项，甚至自定义退避时长 <cite repo="cloudwego/eino" path="adk/retry_chatmodel.go" start="145-215" />。
- **`IsRetryAble`**（已废弃）：仅根据 error 判断是否可重试，向后兼容用途 <cite repo="cloudwego/eino" path="adk/retry_chatmodel.go" start="241-244" />。
- **`BackoffFunc`**：控制每次重试前的等待时长,默认是带抖动的指数退避 <cite repo="cloudwego/eino" path="adk/retry_chatmodel.go" start="246-253" />。

实际执行由 `typedRetryModelWrapper` 完成，它包裹底层模型，根据是否设置 `ShouldRetry` 走新逻辑或兼容旧逻辑 <cite repo="cloudwego/eino" path="adk/retry_chatmodel.go" start="319-337" />。

重试耗尽后返回 `RetryExhaustedError`，其中包裹了最后一次的原始错误；同时通过 `AgentEvent` 发出 `WillRetryError` 事件供上层观测重试过程 <cite repo="cloudwego/eino" path="adk/retry_chatmodel.go" start="92-104" />。

## 2. 故障转移机制（ModelFailoverConfig）

当重试仍失败（或未配置重试）时，可以配置 `ModelFailoverConfig` 切换到备用模型 <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="125-167" />。

- **`ShouldFailover`**：接收输出消息和错误，判断是否需要切换模型；若 context 被取消或错误是 `ErrStreamCanceled`/中断信息，则不会触发 failover <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="195-212" />。
- **`GetFailoverModel`**：根据 `FailoverContext`（含尝试次数、原始输入、上次输出/错误）选择下一个要使用的模型，并可选地转换输入消息 <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="104-166" />。
- **`MaxRetries`**：最大故障转移次数。

具体执行逻辑在 `failoverModelWrapper.Generate` / `Stream` 中：先尝试上次成功的模型（`lastSuccessModel`），失败后再依次调用 `GetFailoverModel` 切换模型直至耗尽 `MaxRetries` <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="225-306" />。流式调用同理，会消费副本流检测 mid-stream 错误再决定是否 failover <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="308-353" />。

## 3. 重试与故障转移的组合

两者通过 `buildModelWrappers` 组装成包装链：重试位于内层，故障转移位于外层——即单个模型先耗尽重试次数，若仍失败才会触发到备用模型的 failover，随后新模型同样会走一遍重试逻辑 <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="49-97" />。测试用例中也验证了"重试耗尽触发 failover"、"全部耗尽报错"、"重试成功则不触发 failover"等各种组合情形 <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="99-148" />。

此外，流式返回的错误也会根据是否还有更多重试/failover机会被包装为 `WillRetryError`，以便上层事件流（`AgentEvent`）跳过失败尝试产生的中间事件，只呈现最终结果 <cite repo="cloudwego/eino" path="adk/wrappers.go" start="437-467" />。

## 4. 与中间件（Middleware）的关系

这两个配置项都定义在 `ChatModelAgentConfig` / `ChatModelAgent` 结构体中，作为独立于 `Handlers`（中间件）的一等字段存在 <cite repo="cloudwego/eino" path="adk/chatmodel.go" start="444-449" />。因此重试/故障转移是框架内置能力，而不是通过 `ChatModelAgentMiddleware` 接口自定义的。

另外，`adk/middlewares/summarization` 包中也有一套独立的 `Failover` 逻辑（`runFailover`），但这是摘要（Summarization）中间件专用的失败处理机制，与主流程的 `ModelFailoverConfig` 是不同的系统 <cite repo="cloudwego/eino" path="adk/middlewares/summarization/summarization.go" start="519-580" />，仅供参考，不属于本问题核心答案。

## Notes

- `ModelRetryConfig` 和 `ModelFailoverConfig` 都是按类型参数化（`TypedModelRetryConfig[M]` / `ModelFailoverConfig[M]`），默认别名对应 `*schema.Message` 类型的 `ChatModelAgent`。
- 组合顺序固定为：重试在内层，故障转移在外层，参见 `adk/retry_chatmodel.go:319-322` 的注释说明。
- `adk/middlewares/summarization/summarization.go` 中的 failover 属于摘要中间件独立实现，与核心 ChatModel 调用失败处理是两套系统，不要混淆。

## Q2
具体怎么使用或者怎么写
### Answer
# 具体用法示例

---

## 1. 仅配置重试（ModelRetryConfig）

最简单的用法：设置 `MaxRetries` 和 `IsRetryAble`，构造 agent 时传入 `ChatModelAgentConfig.ModelRetryConfig` <cite repo="cloudwego/eino" path="adk/chatmodel_retry_test.go" start="110-119" />。

```go
agent, err := NewChatModelAgent(ctx, &ChatModelAgentConfig{
    Name:        "RetryTestAgent",
    Model:       cm,
    ModelRetryConfig: &ModelRetryConfig{
        MaxRetries:  3,
        IsRetryAble: func(ctx context.Context, err error) bool { return errors.Is(err, errRetryAble) },
    },
})
```

- 若不设置 `IsRetryAble`，默认对任何 error 都重试 <cite repo="cloudwego/eino" path="adk/chatmodel_retry_test.go" start="782-808" />。
- 若需要控制退避时间，可传 `BackoffFunc`，每次重试前会调用一次并传入当前尝试次数 <cite repo="cloudwego/eino" path="adk/chatmodel_retry_test.go" start="543-556" />。

### 用 `ShouldRetry` 做更精细的控制

`ShouldRetry` 取代了 `IsRetryAble`，可以基于**输出内容**（不仅仅是 error）判断是否要重试。例如模型返回了不合规的消息内容也可以触发重试 <cite repo="cloudwego/eino" path="adk/chatmodel_retry_test.go" start="1296-1313" />：

```go
ModelRetryConfig: &ModelRetryConfig{
    MaxRetries: 3,
    ShouldRetry: func(ctx context.Context, retryCtx *RetryContext) *RetryDecision {
        if retryCtx.OutputMessage != nil && retryCtx.OutputMessage.Content == "bad" {
            return &RetryDecision{Retry: true}
        }
        return &RetryDecision{Retry: false}
    },
    BackoffFunc: instantBackoff,
},
```

`RetryDecision` 还支持修改下一次重试的输入消息（`ModifiedInputMessages`），例如把系统提示压缩以避免重复出错 <cite repo="cloudwego/eino" path="adk/chatmodel_retry_test.go" start="1521-1537" />。

---

## 2. 仅配置故障转移（ModelFailoverConfig）

`ModelFailoverConfig` 必须同时提供 `ShouldFailover` 和 `GetFailoverModel`，否则 `NewTypedChatModelAgent` 会直接返回错误 <cite repo="cloudwego/eino" path="adk/chatmodel.go" start="490-499" />。典型写法（以 `*schema.AgenticMessage` 为例，`*schema.Message` 用法完全一致）<cite repo="cloudwego/eino" path="adk/agentic_test.go" start="1626-1640" />：

```go
agent, err := NewTypedChatModelAgent(ctx, &TypedChatModelAgentConfig[*schema.AgenticMessage]{
    Name:  "failover-stream-agent",
    Model: m1, // 初始/主模型
    ModelFailoverConfig: &ModelFailoverConfig[*schema.AgenticMessage]{
        MaxRetries: 1, // 最多切换 1 次
        ShouldFailover: func(_ context.Context, _ *schema.AgenticMessage, err error) bool {
            return err != nil
        },
        GetFailoverModel: func(_ context.Context, failoverCtx *FailoverContext[*schema.AgenticMessage]) (model.BaseModel[*schema.AgenticMessage], []*schema.AgenticMessage, error) {
            return m2, nil, nil // 返回备用模型
        },
    },
})
```

- `GetFailoverModel` 返回三个值：备用模型、可选的替换输入消息（传 `nil` 表示沿用原输入）、以及一个可选的立即终止错误 <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="157-167" />。
- 若模型调用出错时 context 被取消，failover 不会触发；但 `context.Canceled` 若不是因为 ctx 本身取消而是模型返回的错误，`ShouldFailover` 依然会被调用 <cite repo="cloudwego/eino" path="adk/failover_chatmodel.go" start="150-155" />。

---

## 3. 同时配置重试 + 故障转移

两者可以叠加使用，执行顺序是：先在当前模型上耗尽重试，再触发 failover 切到下一个模型（该模型同样会经历一遍重试）<cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="64-96" />：

```go
retryCfg := &ModelRetryConfig{
    MaxRetries:  2,
    IsRetryAble: func(_ context.Context, err error) bool { return true },
    BackoffFunc: func(_ context.Context, _ int) time.Duration { return 0 },
}

failoverCfg := &ModelFailoverConfig[*schema.Message]{
    MaxRetries: 1,
    ShouldFailover: func(_ context.Context, _ *schema.Message, err error) bool {
        return err != nil
    },
    GetFailoverModel: func(_ context.Context, fc *FailoverContext[*schema.Message]) (model.BaseChatModel, []*schema.Message, error) {
        return m2, nil, nil
    },
}

agent, err := NewChatModelAgent(ctx, &ChatModelAgentConfig{
    Model:               m1,
    ModelRetryConfig:    retryCfg,
    ModelFailoverConfig: failoverCfg,
})
```

这个组合被 `buildModelWrappers` 内部封装为“重试在内层，failover 在外层”的调用链，测试用 `wrapped.Generate` / `wrapped.Stream` 直接验证了调用次数：m1 先被调用 `1(初次) + MaxRetries` 次，全部失败后才切到 m2，m2 同样会走一遍自己的重试逻辑 <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="81-96" />。

其他组合场景（都在同一测试文件中，可直接参考）：

| 场景 | 说明 | 引用 |
|---|---|---|
| 重试成功，不触发 failover | `ShouldFailover` 永不被调用 | <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="150-196" /> |
| 不可重试错误直接触发 failover | `IsRetryAble` 返回 false，跳过重试直接切模型 | <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="198-246" /> |
| Stream 场景下重试耗尽触发 failover | 中途出错（mid-stream error）同样受理 | <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="248-299" /> |
| Stream 全部耗尽报错 | 返回 `RetryExhaustedError` | <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="301-353" /> |
| `ShouldRetry` 判定内容不合格触发 failover | 结合内容判断而非仅靠 error | <cite repo="cloudwego/eino" path="adk/wrappers_retry_failover_test.go" start="355-405" /> |
